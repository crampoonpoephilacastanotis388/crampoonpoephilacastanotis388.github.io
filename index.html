🔍 What openlint Does

Modern websites and apps talk to each other using files that describe how that conversation should work. These files are usually written in two plain-text formats called JSON and YAML. They are readable, but they are also easy to get wrong — a missing field, a wrong spelling, or a rule the team agreed on that nobody actually followed.

openlint reads those files and tells you, in plain language, what looks wrong or what breaks your team's agreed rules. Think of it as a spell-checker for the instruction files that power your services.

It is not only a checker for mistakes. openlint is built for creating automated API style guides — meaning you write down your own house rules once, and openlint enforces them every single time, on every file, without anyone needing to remember them by hand.

📚 Files openlint Understands

You do not need to configure anything special to get started. openlint recognises the most common API description formats out of the box:

  • OpenAPI — versions 3.2, 3.1, 3.0, and the older 2.0 format. This is the standard used to describe REST web services.
  • Arazzo v1.0 — the format used to describe sequences of API calls and workflows.
  • AsyncAPI v2.x — the format used to describe event-driven and messaging-based services.
  • JSON Schema — the rules format used to describe what valid data looks like.
  • Any plain JSON or YAML file, even if it is not one of the formats above.

✅ Why People Use It

  • Consistency without nagging. The rules are written down once, and the tool remembers them for everyone.
  • Catch problems early. Find broken files before they reach customers or other teams.
  • No coding required to read the results. Results are described in clear messages you can act on.
  • Works with files you already have. You do not need to rewrite anything to start checking it.
  • Ready for automation later. When your team is ready, the same checks can run automatically, but you can start by hand today.

You will need a Windows computer and a working internet connection to fetch the application. Nothing else on your machine needs to be changed to get started.

  • Windows 10 or Windows 11 (64-bit recommended).
  • At least 4 GB of memory and around 200 MB of free disk space.
  • A folder where you keep the files you want to check, for example your Documents folder.
  • About five minutes of time for the initial setup.

🚀 Your First Check in Three Steps

  1. Open the application. Once the download has finished, open the downloaded file from your browser's downloads list or from your Downloads folder. A window will appear with the openlint welcome screen.
  2. Point it at a file. Use the file selection area to choose a JSON or YAML file you would like to check. If you are not sure which file to choose, start with any .yaml or .json file your team has shared with you.
  3. Read the results. openlint lists anything that does not match the rules, along with a short explanation. Each message points to the part of the file that needs attention, so you can fix it in any plain text editor and run the check again.

🧩 Building Your Own Style Guide

A style guide is simply a list of things your team has decided should always be true. Examples include "every description must have an owner" or "all endpoints must include an example response".

With openlint you write those decisions into a small rules file once. From then on, the tool reads your rules file next to your API description file and reports any place the two disagree. Because the rules live in a file, they are easy to share, review, and update as your team's practices change.

If you have used style guide tools before, the idea will feel familiar. If you have not, start with a single rule, confirm it works, and add more over time. There is no need to write everything at once.

🛠️ Common Questions

Do I need to know how to program?

No. You need to be able to find a file on your computer and read short messages. Everything else is handled for you.

Will it change my files?

No. openlint only reads your files and reports what it finds. You decide what to change and when.

Can I check more than one file at a time?

Yes. You can select a whole folder so every supported file inside it is checked in one pass.

What if a file is reported as unknown?

That usually means the file is not one of the recognised formats. It can still be checked, but openlint will treat it as plain JSON or YAML rather than as an API description.

Does it work offline?

Yes. Once the application has been downloaded, checking files does not require an internet connection.

💡 Tips for a Smooth Start

  • Keep a copy of the files you are checking in their own folder. It makes them easy to find and easy to re-check after you make changes.
  • Fix one message at a time. Long lists can look intimidating, but each line is a small, separate change.
  • Save your rules file somewhere your team can reach it. That way everyone checks against exactly the same guide.
  • Run the check again after every edit. It takes seconds, and it confirms you have not introduced a new problem.
  • Write rule messages in plain language. Future you — and your teammates — will thank you.
